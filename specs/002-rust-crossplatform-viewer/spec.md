## Clarifications

### Session 2026-11-16

- Q: Which desktop operating systems should v1 target? -> A: Windows 10/11, macOS (Apple Silicon and Intel), and Linux (X11 and Wayland).
- Q: How should camera RAW (8 extensions), `.heic`/`.heif`, `.avif`, and `.jp2` formats be supported in v1? -> A: Use memory-safe core decoders for all standard raster/layered/HDR/archive formats and delegate camera RAW, `.heic`/`.heif`, `.avif`, and `.jp2` to host OS platform imaging codecs where available (reporting a clear localized unsupported/missing-codec message if the host lacks a codec rather than crashing).
- Q: How should OS shell integration, default-app associations, and auto-update installation work on non-Windows platforms? -> A: Follow OS-idiomatic equivalents on each platform (Windows Explorer context menu + HKCU Default Apps + installer/portable auto-update; macOS `.app` document associations + Finder Open With + `.dmg`/bundle update flow; Linux user `.desktop`/MIME associations + package/archive update flow).
- Q: Must the new cross-platform viewer preserve full backward read/write compatibility with existing `v1.0.6` `settings.json` files? -> A: Yes — read and write the existing `v1.0.6` JSON schema (including v1–v3 migration, field names, and finite bounds recovery) seamlessly on Windows upgrades and across platforms.
- Q: How should embedded ICC color profiles (Display P3, Adobe RGB, CMYK, etc.) be handled during rendering across Windows, macOS, and Linux? -> A: Convert images containing embedded non-sRGB or CMYK ICC profiles accurately to sRGB during decoding, while taking a zero-transform fast path for untagged or standard sRGB images (safely ignoring malformed profiles without crashing).
- Q: How should clicking "Update Now" behave on macOS and Linux compared to Windows? -> A: Enforce identical HTTPS + SHA-256 verification on all platforms; keep silent installer/portable self-replacement + relaunch on Windows, and download verified release artifacts (`.dmg`/package) cleanly on macOS and Linux to open the installer/folder (or fall back to the HTTPS release page if unsupported).
- Q: How should primary modifier shortcuts (`Ctrl` vs `Cmd`), `Esc` window/quit behavior, and Finder/CLI launch arguments work across OSes? -> A: Use OS-idiomatic primary modifiers (`Cmd` on macOS with both `Alt+Enter` and `Ctrl+Cmd+F` fullscreen support; `Ctrl` on Windows and Linux); `Esc` closes active dialogs first or closes the active viewer window (exiting when the last window closes); CLI remains fail-closed at-most-one-path (ignoring benign macOS Finder `-psn_*` session flags while Finder OpenFile events open a dedicated viewer window per item).
- Q: How should Zero Trust pre-checks and missing-codec fallbacks work when delegating RAW, `.heic`/`.heif`, `.avif`, and `.jp2` to host OS platform codecs? -> A: Enforce the same `8 KB` leading binary signature inspection, stream byte cap (`512 MB`), and pre-decode metadata pixel/stride limit (`MaxImageMegapixels`) BEFORE pixel allocation in any OS platform codec, failing closed with a safe localized notice whenever pre-decode dimensions cannot be verified or when optional OS codecs (e.g., on Linux) are unavailable.
- Q: Should high-resolution JPEG thumbnail/viewport pre-decoding require C-FFI DCT `n/8` scaling or use pure memory-safe decoding + SIMD downscaling? -> A: Prioritize pure memory-safe decoding combined with SIMD downscaling (bounded by `MaxImageMegapixels` and cached viewport textures) to achieve `SC-001`–`SC-002` speed parity without introducing C-FFI JPEG attack surface; consider C/OS reduced-decode fallback only if measured benchmarks miss latency targets.
- Q: How should persisted window coordinates (`Left`/`Top`) and canvas drag-move/edge-hover behave on Linux Wayland where clients cannot access global screen coordinates? -> A: Restore full window size, maximized state, and `(Left, Top)` coordinates on Windows, macOS, and Linux X11; on Wayland, restore width/height/maximized state only while delegating initial placement to the compositor, using compositor-delegated window dragging, and detecting edge hover within client surface coordinates.
- Q: Beyond the `512 MB` per-entry uncompressed cap, what archive-wide limits MUST guard against ZIP/CBZ exhaustion attacks? -> A: Enforce composite archive caps on open: at most `50,000` entries per archive, `<= 64 MB` central directory metadata, and `<= 4 GB` total archive container size (in addition to the configurable `512 MB` per-entry uncompressed streaming cap), failing closed on violation.
- Q: How should floating-point HDR (`.exr`, `.hdr`) and high-bit-depth (`16-bit` PNG/TIFF/RAW) images be tone-mapped for display and filtering? -> A: Apply lightweight automatic exposure/soft tone mapping with sRGB gamma encoding for floating-point HDR inputs (preventing highlight blowout) and consistent normalization for `16-bit` integer inputs prior to display/filtering.
- Q: How should smooth trackpad pixel scrolling and pinch-to-zoom gestures interact with the default notched mouse-wheel navigation rule? -> A: Preserve notched mouse-wheel actions (`prev/next` default, modifier zoom, `Shift+Wheel` vertical pan), apply an accumulated pixel-delta threshold with step cooldown to continuous precision trackpad scrolling to prevent accidental rapid skipping, and natively support trackpad pinch-to-zoom gestures across platforms.

## Overview & Platform Pivot Context

This specification defines the complete functional, usability, security, reliability, and performance requirements for re-architecting **ImageViewer** as a **Rust-based cross-platform desktop application** targeting **Windows 10/11 (x64)**, **macOS (Apple Silicon and Intel)**, and **Linux (X11 and Wayland)**.

All existing user-facing workflows, keyboard shortcuts, mouse interactions, viewing modes, image filters, animated/multi-page playback rules, EXIF metadata inspection, archive browsing, Zero Trust security defenses, auto-update flows, and Korean/English localization from the `v1.0.6` baseline MUST be preserved while matching or exceeding every measured latency and memory benchmark.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Fast Core Viewing, Navigation, and Viewport Manipulation (Priority: P1)

As a user opening an image file, local folder, or `.zip`/`.cbz` archive via file explorer, drag-and-drop, native open dialog, or command line, I want the viewer to launch quickly, render crisp images across all display and zoom modes with frameless ergonomic controls, and switch images rapidly without stuttering or waiting on previously skipped large files.

**Why this priority**: Instant image opening, responsive keyboard/mouse navigation, natural filename sorting, and multi-mode viewport fitting represent the primary daily value of ImageViewer across all desktop platforms.

**Independent Test**: Can be fully tested by launching the app against folders and mixed-format `.zip`/`.cbz` archives, exercising every display mode (`0`/`7`/`8`/`9`), zoom/pan/rotation/flip action, wrap-around toggle, natural ordering (`image2 < image10`), and rapid arrow-key sweeps (`100–150 ms` cadence) while asserting latency, visual parity, and responsive input.

**Acceptance Scenarios**:

1. **Given** a local image file, folder, or `.zip`/`.cbz` archive dropped onto the window or opened via dialog or CLI argument, **When** the source loads, **Then** the viewer MUST list supported images in natural filename order without extracting archives to disk, display the selected/first image immediately (supporting multiple independent viewer instances across opened paths), and permit configurable wrap-around navigation.
2. **Given** an image containing EXIF orientation tags (`1–8`) viewed in Original (`0`), Fit Width (`7`), Fit Height (`8`), or Fill (`9`, default) mode, **When** loaded and viewed as the user zooms (`+`/`=`/`-`, reset `Ctrl+0` / OS primary modifier), drags to move the frameless window or pan when zoomed/fullscreen, rotates (`R`/`L`), or flips (`H`/`V`), **Then** initial EXIF orientation MUST be applied automatically before user transforms (respecting swapped aspect ratios on orientations `5–8`), while user transforms remain non-destructive (view-only), reset automatically upon navigating to another image, and preserve crisp HiDPI/fractional display scaling across monitors.
3. **Given** rapid consecutive navigation (`100–150 ms` per step) across high-resolution images, **When** an obsolete high-resolution decode would otherwise occupy worker slots, **Then** the viewer MUST immediately start decoding the newly selected image, leverage directional prefetching (`+1`/`+2`/`-1`, burst up to `+4`, and slideshow peek), display a scaled cached thumbnail placeholder after `250 ms` if high-res is still pending (loading indicator at `500 ms`), and discard stale outputs cleanly.
4. **Given** a user interacting with top/bottom floating chrome bars, **When** they toggle independent bar pins or press `` ` `` (global pin toggle), double-click the canvas, or press fullscreen toggle (`Alt+Enter` / OS fullscreen shortcut), **Then** unpinned bars MUST appear smoothly on top/bottom edge hover and hide otherwise, while pinned bars stay visible even in borderless fullscreen; `Esc` MUST close active dialogs first or exit the viewer.

### User Story 2 - Rich Media Formats, Animations, Multi-Page, Filters, Slideshow, and EXIF (Priority: P2)

As a user inspecting diverse photo collections, animated graphics, multi-page documents, or camera metadata, I want animated GIF/WebP/APNG playback, multi-page TIFF navigation, non-destructive screen-pixel filters, configurable slideshows, thumbnail browsing, folder watching, and detailed EXIF panels to work identically across desktop platforms.

**Why this priority**: Feature parity across animations, multi-page TIFFs, screen-scale filters, image list management, slideshow scheduling, and EXIF inspection differentiates ImageViewer from bare-bones viewers and fulfills user expectation of zero lost functionality.

**Independent Test**: Can be fully tested by opening multi-page TIFF, large multi-frame animated WebP/GIF/APNG, high-DPI/zoomed images with `Smooth`/`Smooth+Sharpen` filters, camera-tagged JPEGs/RAWs, and live-modified folders while verifying visual output, memory caps, elapsed-time frame accuracy, slideshow random non-repetition, and EXIF readout.

**Acceptance Scenarios**:

1. **Given** an animated GIF, WebP, or APNG file (including >200-frame high-resolution animations), **When** animation playback is enabled, **Then** the viewer MUST display frame 1 immediately and stream/cache remaining frames within the configured memory budget (`512 MB` full cache or `128 MB` forward ring buffer), bypass display filters, honor wall-clock frame delays (normalizing `0–10 ms` GIF frames—and WebP only when *all* frames are `0–10 ms`—to `100 ms`), and show the bottom-left translucent frame status overlay.
2. **Given** a multi-page TIFF or `.ico`/`.cur` file, **When** displayed, **Then** `.ico`/`.cur` MUST show the largest frame, and multi-page TIFF MUST start at page 1, support `PageUp`/`PageDown` navigation, display page position (`n/m`) on the bottom bar, and preserve active rotation/flip across page changes.
3. **Given** `None` (`U`), `Smooth` (`I`), or `Smooth + Sharpen` (`S`) filter modes with configured strengths (`SmoothSigma` `0.1–3.0` default `0.5`, `SharpenSigma` `0.1–5.0`, `SharpenAmount` `0.1–5.0`), **When** viewing zoomed or small images, **Then** filter radius MUST remain calibrated to **screen pixels** (dividing by display scale) so zooming into small images does not over-blur details.
4. **Given** active slideshow (`Space`, `5–90 s`, Sequential or non-repeating Random, Repeat toggle), thumbnail strip (`48–256 px`, optional scrollbar, `300`-item cap), Image List dialog (`Enter`, sortable by Name/Date/Size), EXIF Info panel (`Tab`), or Folder Watcher (`0.7 s` debounce), **When** each feature runs, **Then** all states MUST update smoothly, manual moves during slideshow MUST reset the slideshow timer, and deleting the active watched file MUST advance cleanly to the same list index.
5. **Given** diverse image format extensions across the supported catalog, **When** users open them across Windows, macOS, and Linux, **Then** all standard raster, HDR, icon, layered, and archive formats MUST decode consistently via the viewer's memory-safe core pipeline across every OS, while camera RAW (`.dng`/`.cr2`/`.cr3`/`.nef`/`.arw`/`.orf`/`.rw2`/`.raf`), `.heic`/`.heif`, `.avif`, and `.jp2` MUST utilize host OS platform imaging codecs where available and display a clear, non-crashing localized notice whenever a host platform lacks an optional codec (such as on minimal Linux setups).

### User Story 3 - Zero Trust Input Defense, Cross-Platform Native Integration, Settings, Localization, and Updates (Priority: P3)

As a user opening files from untrusted sources and running the app as an integrated desktop viewer on Windows, macOS, or Linux, I want strict protection against disguised scripts, decompression bombs, traversal attacks, and path leaks, alongside preserved Korean/English UI, persisted settings, About diagnostics, release updates, and OS-native file associations.

**Why this priority**: Maintaining Zero Trust security posture, privacy-safe diagnostics, backward-compatible preferences/localization, and seamless OS integration ensures the cross-platform app is safe for untrusted downloads and feels native on every host OS.

**Independent Test**: Can be fully tested via hostile-input negative security suites (UTF-32/16/8 polyglot scripts disguised as images, ZIP slip/symlink/deceptive-size bombs, extreme pixel dimensions, corrupted/oversized settings, non-HTTPS update feeds, log injection) plus platform integration checks for OS file opening, settings persistence, localization switching, and About clipboard export.

**Acceptance Scenarios**:

1. **Given** any untrusted image, archive entry, CLI argument, or persisted settings file, **When** processed, **Then** the app MUST inspect binary content signatures (up to `8,192` leading bytes across UTF-32/16/8 BOMs and whitespace padding) before decoding to block SVG/MVG/PDF/PS/HTML/script payloads, enforce pre-decode pixel limits (default `150 MP`, UI `10–500 MP`, clamp `10–1000 MP`) and `checked` stride bounds, cap archive stream reads (default `512 MB`) dynamically during streaming, reject symlink/reparse/Zip-Slip escapes, show clear messages for encrypted ZIPs, and sanitize corrupted/oversized (`> 64 KB`) or non-finite settings back to safe defaults.
2. **Given** runtime errors, slow-render diagnostics (`>= 300 ms`), or normal file operations, **When** logs are written to the per-user log directory (7-day retention) or surfaced in UI dialogs, **Then** logs MUST omit all full host directory paths (retaining filename-only identifiers) and strip newline control characters, while non-blocking log writers drain cleanly on shutdown without stalling exit.
3. **Given** Settings, About (`Version`, runtime OS/architecture, third-party library table dynamically reflecting loaded library versions, project URL, and clipboard Copy button), and auto-update checks (once per 20–24h cycle starting ~5s after launch, manual check, Skip Version, Dismiss, `https://`-only + SHA-256 verification), **When** triggered, **Then** the user can browse release notes, apply/download verified updates cleanly, and inspect UI in Korean (`ko`) or English (`en`) consistently.
4. **Given** OS desktop integration, packaging, and update workflows, **When** invoked across platforms, **Then** each OS MUST deliver idiomatic native integration: Windows preserves HKCU Explorer context menus (`--register-shell` / `--unregister-shell`), Default Apps registration, and silent installer/portable self-replacement + relaunch; macOS provides `.app` bundle document-type associations (Finder Open With / default viewer), `.dmg` distribution, and SHA-256-verified artifact download + installer/folder launch; Linux provides user-level `.desktop`/MIME associations and SHA-256-verified package/AppImage download + launch (with HTTPS release-page fallback across non-self-updating modes).

### Edge Cases

- What happens when an image file carrying `.png` or `.tga` starts with UTF-32 LE/BE (`FF FE 00 00` / `00 00 FE FF`), UTF-16 LE/BE, or `> 512` bytes of whitespace followed by `<svg`, `<?xml`, `%PDF`, `%!`, `push `, or `viewbox`?
- How does viewport-scaled pre-decoding respond when a user switches from Fit Width to Original (`0`) or zooms in past the downscaled cached texture? (Must maintain/reload full-resolution pixels in the background when zoomed past display resolution and swap seamlessly without flicker.)
- What happens when a compressed archive entry lies about its uncompressed size in header metadata, uses POSIX/DOS symlink bits, uses `..\` traversal or sibling-directory prefixes, or is password-encrypted?
- How does the app react when opening an extreme-dimension image (`width * 4` overflowing 32-bit math) or an animation whose decoded frames would exceed `512 MB`?
- How do platform shortcuts avoid OS conflicts (e.g., `Ctrl+O` / `Ctrl+0` on Windows/Linux vs `Cmd+O` / `Cmd+0` on macOS, and Windows `Alt+Enter` vs macOS `Ctrl+Cmd+F` alongside `Alt+Enter`) while keeping documented single-key shortcuts (`R`, `L`, `H`, `V`, `` ` ``, `U`, `I`, `S`, `Space`, `Tab`, `Enter`, `Esc`, `0`/`7`/`8`/`9`) identical?
- What happens when a user switches folders or closes the viewer mid-decode, mid-thumbnail-generation, or mid-update-check?
- What happens on Linux (Wayland/X11) when a user drags files from a desktop file manager, restores window state, or opens an `.heic`/`.cr3` file without optional OS codecs installed? (Drag-and-drop MUST work reliably under both Wayland and X11; Wayland restores window width/height/maximized state cleanly while delegating `(Left, Top)` coordinates and drag moves to the compositor; missing optional OS codecs MUST display a non-crashing localized format notice while still enforcing Zero Trust header/size guards.)
- What happens when a precision trackpad emits continuous high-frequency two-finger scroll events or pinch-to-zoom gestures while mouse-wheel navigation is set to Previous/Next? (Accumulated pixel-delta thresholds and cooldown prevent multi-image overshooting on a single swipe, while pinch gestures zoom smoothly around the cursor.)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (Core Viewing & Viewport Modes)**: System MUST load local images, folders, and `.zip`/`.cbz` archives (multi-instance capable; no disk extraction for archives), sort entries in natural filename order, support optional wrap-around navigation, automatically orient images according to EXIF `Orientation` (`1–8`, accounting for swapped dimensions on tags `5–8`), convert non-sRGB/CMYK embedded ICC profiles accurately to sRGB (taking a fast pass-through path for untagged/sRGB images and ignoring corrupt ICC profiles safely), apply lightweight automatic exposure/soft tone mapping with sRGB gamma encoding for floating-point HDR inputs (`.exr`/`.hdr`) and consistent normalization for `16-bit` integer images, and render across Original (`0`), Fit Width (`7`), Fit Height (`8`), and Fill (`9`, default) modes with zoom, pan, 90° CW/CCW rotation (`R`/`L`), and horizontal/vertical flip (`H`/`V`) reset on image change while adapting cleanly to monitor DPI / fractional scale changes.
- **FR-002 (Full Ergonomic Controls & Window Chrome)**: System MUST provide a frameless custom titlebar and auto-hiding translucent floating top/bottom bars controlled by independent pins and global `` ` `` pin toggle (detecting edge hover relative to window client coordinates so Wayland compositors remain fully supported), borderless fullscreen toggle (`Alt+Enter` across all OSes plus `Ctrl+Cmd+F` on macOS), double-click maximize/restore, canvas drag window move (using compositor-delegated window move on Wayland; panning in zoom/fullscreen), `Esc` closing active dialogs first or closing the current window (exiting the application when the last window closes), configurable mouse wheel action (prev/next vs zoom with modifier inversion), `Shift+Wheel` vertical pan, mouse back/forward buttons, accumulated pixel-delta thresholding on precision trackpad smooth scrolling (preventing unintentional multi-image jumps while preserving discrete mouse-wheel behavior) plus native trackpad pinch-to-zoom gestures, checkerboard/solid backgrounds, and complete keyboard shortcut parity adapted cleanly to OS primary modifiers (`Cmd` on macOS, `Ctrl` on Windows and Linux).
- **FR-003 (Rich Media Playback, Filtering & Inspection)**: System MUST support multi-page TIFF navigation (`PgUp`/`PgDn`, preserving rotation/flip), `.ico`/`.cur` largest-frame selection, GIF/WebP/APNG wall-clock animation playback (respecting frame-delay normalization rules and animated overlay info), screen-pixel-calibrated `None`/`Smooth`/`Smooth+Sharpen` filters (bypassed on animations), thumbnail strip (`48–256 px`, toggleable scrollbar, `300`-item cache), sortable Image List dialog (`Enter`), EXIF metadata panel (`Tab`), configurable slideshow (`Space`, `5–90 s`, sequential/random non-repeat/repeat), and debounced (`0.7 s`) folder watching.
- **FR-004 (Performance Parity & Responsiveness)**: System MUST achieve decode, resize, navigation, and memory performance equal to or better than the `v1.0.6` Windows baseline across all target OSes via a memory-safe core decoding and SIMD resizing pipeline: viewport-scale downsampling without C-FFI JPEG memory-safety exposure (plus asynchronous full-resolution upgrade when zooming past the cached display size), GPU/display-stage scaling when image dimensions modestly exceed viewport (`>= 60%`), non-blocking parallel decoding with immediate preemption of stale work, directional/slideshow lookahead prefetching, `250 ms` thumbnail placeholder / `500 ms` spinner thresholds, LRU decoded cache (`<= 8` full bitmaps), and bounded animation streaming (`<= 512 MB` pre-decode or `<= 128 MB` forward ring buffer).
- **FR-005 (Zero Trust Input & Archive Security)**: System MUST treat all images (including payloads delegated to host OS codecs), archives, CLI inputs, drag-and-drop paths, update payloads, and config files as untrusted: inspect binary headers (`<= 8,192` bytes, multi-BOM order + whitespace guards) before both core and OS-codec decoding to block SVG/MVG/PDF/PS/HTML scripts, enforce overflow-safe stride math and configurable pre-decode pixel limits (`150 MP` default, `10–1000 MP` bounds) prior to pixel allocation (failing closed if pre-decode dimensions cannot be verified or an OS codec is missing), enforce streaming uncompressed byte caps (`512 MB` default per entry) alongside archive-wide fail-closed caps (`<= 50,000` entries, `<= 64 MB` central directory metadata, `<= 4 GB` archive container size), block Zip-Slip/symlink traversal and reparse escapes, handle encrypted ZIPs gracefully, enforce `64 KB` max config file size with `NaN`/infinite/bounds sanitization, fail closed on invalid/conflicting CLI arguments (accepting at most one target path or valid shell switch while ignoring benign OS Finder `-psn_*` flags and dispatching macOS Finder file-open events cleanly per window), and strictly use `https://` + SHA-256 verification + payload byte limits for remote updates.
- **FR-006 (Privacy-Safe Diagnostics & Deterministic Teardown)**: System MUST omit full host user directory paths and strip control characters (`\r`/`\n`) from all log entries and generic UI error dialogs—echoing user-supplied full paths ONLY when reporting an explicit missing command-line target error—(retaining filename-only logging, `>= 300 ms` slow-render traces, and 7-day log retention in per-user data directories), flush pending logs/launches safely without blocking shutdown, and cancel/release all workers, watchers, timers, and buffers deterministically upon source switch or window exit.
- **FR-007 (Localization, Diagnostics Dialog & Updates)**: System MUST preserve full Korean (`ko`) and English (`en`) UI localization, provide persisted settings (`Window`, `Display`, `Navigation`, `Slideshow`, `Thumbnail`, `Filter`, `Limits`, `Update`) with full backward read/write compatibility for existing `v1.0.6` `settings.json` schemas (camelCase properties, string enums, comment/trailing-comma tolerance, v1–v3 migration, finite bounds recovery, and safe Wayland size/maximize-only restoration without failing on absent global coordinates), render the About dialog (`App/OS/Runtime` versions, dynamically queried third-party library notices/licenses/URLs, project link, clipboard Copy button), and check GitHub releases on schedule (~5s startup delay, daily interval, Skip Version / Dismiss / Install flow).
- **FR-008 (Target OS Scope, Codec Strategy & Idiomatic OS Integration)**: System MUST support **Windows 10/11 (x64)**, **macOS (Apple Silicon and Intel)**, and **Linux (X11 and Wayland)**; MUST decode all standard formats (`.jpg`/`.jpeg`/`.jpe`/`.jfif`, `.png`/`.apng`, `.gif`, `.bmp`/`.dib`, `.tif`/`.tiff`, `.webp`, `.ico`/`.cur`, `.jxl`, `.tga`, `.psd`, `.dds`, `.pcx`, `.qoi`, `.ppm`/`.pgm`/`.pbm`/`.pnm`, `.hdr`, `.exr`, `.zip`/`.cbz`) consistently via its built-in memory-safe core across all 3 OSes while delegating camera RAW (`.dng`/`.cr2`/`.cr3`/`.nef`/`.arw`/`.orf`/`.rw2`/`.raf`), `.heic`/`.heif`, `.avif`, and `.jp2` to host OS platform codecs where available (failing gracefully with an informative localized message when a host lacks a codec); and MUST provide OS-idiomatic file-association, packaging, and verified update behavior (Windows Explorer `--register-shell`/`--unregister-shell` + HKCU Default Apps + installer/portable self-update + relaunch; macOS `.app` document associations + `.dmg` verified download/open; Linux XDG `.desktop`/MIME + verified package/AppImage download/open, falling back safely to the HTTPS release page).

### Key Entities

- **Media Source & Entry**: Abstraction over local folders, individual files, and read-only ZIP/CBZ archives holding sorted natural-order entries (`ImageInfo`), modified timestamp, byte size, and security-validated boundaries.
- **Decoded Frame & Animation Stream**: Bounded-pixel bitmap or frame-sequence handle (`RGBA`/GPU texture) carrying source dimensions, EXIF metadata, color profile metadata, and deterministic reference/LRU ownership.
- **Viewport & Chrome State**: Non-destructive geometric transform (`DisplayMode`, zoom scale, pan offset, 90° rotation steps, H/V flip flags) paired with bar pin state, hover visibility, and fullscreen restore geometry.
- **Viewer Configuration**: Per-user persisted JSON settings (`<= 64 KB`, schema-versioned, finite-validated bounds) covering window placement, display background/mouse-wheel/filter preferences, safety caps, and update check timestamps/skipped version.
- **Release Update Package & OS Registration**: Verified HTTPS release descriptor (`Version`, tag, release URL, binary asset metadata, required 64-hex SHA-256 checksum) and per-user OS file-association/context-menu registration state.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001 (Single-Image & Fullscreen Speed Parity)**: On a representative 32-image mixed JPEG/PNG archive (`2592×1728` max) at `1280×800` Fit Width on baseline hardware, average decode + display time is **<= 36 ms** (`<= 95 ms` max), and at `2560×1440` fullscreen is **<= 49 ms** average (`<= 137 ms` max) — matching or beating `v1.0.6`.
- **SC-002 (Rapid Navigation & Slideshow Responsiveness)**: During `100–150 ms` rapid sequential key stepping, median/average frame presentation completes in **<= 22 ms** (`<= 53 ms` max), and slideshow transitions complete in **<= 16 ms** average (`<= 30 ms` max) with zero UI input freeze.
- **SC-003 (Large Animation & Memory Efficiency)**: A high-resolution `1080×1920`, `267`-frame animated WebP starts displaying frame 1 in **< 250 ms**, maintains total application memory within **<= 470 MB**, and averages **<= 5% CPU** during playback without frame-timing drift.
- **SC-004 (Feature & Shortcut Parity)**: **100%** of documented keyboard shortcuts, mouse actions, display modes (`0`/`7`/`8`/`9`), screen-scale filter modes, EXIF fields, multi-page TIFF controls, slideshow options, thumbnail controls, Image List sorting, settings persistence, and `ko`/`en` localizations pass cross-platform acceptance verification.
- **SC-005 (Zero Trust Security & Zero Path Leakage)**: **100%** of adversarial test cases (multi-encoding spoofed script payloads, decompression bombs, integer dimension overflows, Zip-Slip/symlink escapes, oversized/corrupt configs, non-HTTPS/checksum-mismatched updates, and fail-closed CLI inputs) are safely rejected, and diagnostic log files contain **zero** full user host directory paths.
- **SC-006 (Cross-Platform Native Build & Automated Verification)**: Core domain, decoding, security validation, viewport geometry, slideshow timing, and session lifecycle suites compile and execute natively in CI and developer environments across every selected target OS with zero skipped assertions.

## Assumptions

- **Platform Governance Transition**: Adopting Rust as a multi-platform desktop technology is governed by `.specify/memory/constitution.md` (`v2.0.0`, ratified for Rust across Windows 10/11, macOS, and Linux while preserving Principles I–VII: Korean UX/summaries, English code/specs, strict TDD, zero fake mocks/bypasses, EBSE research, skeptical verification, and Zero Trust).
- **Backward Data Continuity**: Existing `settings.json` semantics and user expectations (finite bounds, `150 MP` pixel cap default, `512 MB` zip entry cap default, `0.5` smooth sigma default, `ko`/`en` resources) remain intact, stored in each OS's idiomatic per-user application data directory (`%LOCALAPPDATA%\ImageViewer` on Windows, `~/Library/Application Support/ImageViewer` on macOS, XDG config/data dirs on Linux if targeted).
- **Performance Headroom Targets**: Benchmarks in `SC-001`–`SC-003` are anchored directly to the measured `v1.0.6` results in `README.md` (`test.zip`, desktop hardware); cross-platform Rust architecture should target matching or outperforming these numbers via SIMD image scaling, reduced-scale decoding, and GPU-accelerated texture presentation.
- **Encrypted Archives**: Password-protected ZIP/CBZ archives remain unsupported with a clear, safe per-item notice rather than prompting for credentials or crashing.
- **Windows 11 Context Menu Scope**: Preserves `v1.0.6` zero-elevation HKCU Explorer context-menu verbs (visible under "Show more options" / `Shift+F10` on Windows 11) so portable single-binary and unpackaged per-user deployments remain clean without requiring MSIX Sparse Package identity wrapping in v1.
